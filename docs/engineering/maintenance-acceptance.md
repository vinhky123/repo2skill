# Commit maintenance acceptance

This record maps the delivered maintenance lifecycle to its implementation tests and records the verification actually run for Task 10. The Task 10 integration test, focused suite, full suite, and installed-wheel smoke ran on Windows with Python 3.13.15. The six configured CI cells remain unexecuted remotely. The complete implementation tradeoff record is in [maintenance decisions](maintenance-decisions.md).

The named checks include `test_maintain_command_grammar`, `test_default_status_requires_approval`, `test_status_does_not_request_user_approval_for_current_auto_grant`, `test_corrupt_maintenance_state_exits_seven`, `test_skip_does_not_advance_baseline_or_repeat_same_event`, `test_stale_approval_reports_finding_without_running_worker`, `test_approve_runs_exact_job_in_foreground_and_reports_unavailable_agent`, and `test_busy_first_approval_reuses_binding_and_second_approve_runs_once`. `tests/test_cli.py::test_parser_exposes_all_canonical_commands_and_codex_grammar` checks the package-level command surface.

## Hook events, approval, and policy

`tests/maintenance/test_apply.py::test_commit_to_approved_apply_to_verified_baseline` exercises a committed post-commit event through `process_hook`, approval of that exact job through the CLI, a real worker with explicit fake probe/invoke callbacks, evidence-backed claim validation, apply/export, live manifest hashes, and a verified baseline. It confirms human bytes before and after the owned AGENTS.md block survive. After that first apply advances the baseline, the test commits another change while the worker still holds its OS lease and calls the real hook path. The late job is pending with no approval source or binding at hidden-worker handoff; a fresh auto grant is then rechecked by a real fake-adapter worker drain. The test checks the second target, baseline, accepted output, and exactly two fake probe/invoke pairs. The first job uses ask approval; the second job's auto authority comes from the newly configured current grant.

Hook parsing, event recovery, and bounded input are covered by `tests/maintenance/test_git.py::test_hook_event_resolves_current_commit_for_post_commit_and_merge` and `tests/maintenance/test_hooks.py::test_completed_git_hook_is_recovered_by_manual_catch_up` (post-merge, post-rewrite, and post-checkout parameters), `test_post_rewrite_record_count_is_bounded`, `test_hook_stdin_read_is_byte_and_time_bounded`, `test_hook_stdin_byte_cap_is_deferred_with_catch_up_notice`, and `test_no_baseline_hook_defers_until_explicit_rebuild`. The real installed-wrapper Git commit test is `test_windows_git_bash_runs_installed_wrapper_for_real_commit`; it ran on the local Windows host. A branch switch, missing object, or unprovable baseline is covered by `tests/maintenance/test_recovery.py::test_branch_switch_or_missing_object_requires_rebuild` and does not advance the applied baseline.

User approval binding and policy-grant revision/revocation are covered by `tests/maintenance/test_approval.py::test_approve_binds_job_fingerprints`, `test_policy_change_does_not_approve_pending_job`, `test_auto_grant_only_dispatches_job_observed_at_current_revision`, `test_auto_grant_is_versioned_and_revocable`, `test_state_only_auto_does_not_authorize_worker`, and `test_worker_revalidates_auto_grant_under_final_mutation_lock`. `tests/maintenance/test_recovery.py::test_reachable_events_coalesce_without_transferring_approval` and `test_queued_successor_refreshes_after_apply_with_new_binding` cover fresh successor bindings and non-transfer of predecessor approval.

## Paths and platform-specific behavior

The current path/reparse, casing, and newline acceptance is mapped to `tests/test_ledger_transactions.py::test_writes_require_lock_and_reject_redirected_state_paths`, `test_long_lived_store_rechecks_redirected_state_directory_before_read`, and `test_store_rejects_final_component_case_collision`; `tests/test_output_fs.py::test_guarded_output_operations_reject_redirected_ancestors`; `tests/maintenance/test_git.py::test_materialize_rejects_symlink_mode_on_every_platform`; `tests/test_export_recovery.py::test_mixed_eol_is_a_preflight_conflict`; and `tests/maintenance/test_git.py::test_nul_paths_preserve_renames_and_newlines`. `tests/test_cli_lifecycle.py::test_doctor_reports_read_only_environment_checks` checks reported state/output permission values without changing the fixture; this is a read-only capability report, not a simulated denied-write test.

Executable discovery and platform launch behavior are covered by `tests/maintenance/test_agent_capability.py::test_probe_discovers_codex_on_path_or_reports_unavailable`, `tests/maintenance/test_hooks.py::test_posix_wrapper_publication_has_executable_mode`, `test_wrapper_launcher_avoids_repo_shadow_module_and_windows_console`, `test_hidden_worker_launch_preserves_custom_confined_state_dir`, `test_hidden_entrypoint_opens_exact_custom_state_dir`, and `tests/maintenance/test_worker.py::test_hidden_auto_worker_waits_for_busy_lease_then_drains_current_job` plus `test_hidden_ask_worker_never_runs_a_user_approved_job`. Lease death/release behavior is also covered by `tests/test_ledger_transactions.py::test_two_processes_contend_fail_fast_then_reread_and_update` and `test_os_releases_lock_when_process_dies`.

Windows cannot create a Git path containing a newline; `test_nul_paths_preserve_renames_and_newlines` uses the parser fixture on Windows and exercises the Git rename/add path on POSIX. The installed-wrapper shell test skips when its expected Git for Windows Bash location is unavailable. Descendant cleanup tests require Windows `taskkill`/`tasklist` utilities on Windows. POSIX executable-mode checks are conditional, and native directory-symlink fixtures may skip when the host cannot create one. These are fixture capability limits; no product-platform result is inferred from a skipped fixture.

Maintenance Git reads are bounded to 256 committed files, 2 MiB per source file, 16 MiB total context, a 10 second shared Git budget, 8 MiB diff output, 32 MiB tree output, and 1 MiB hook stdin. `post-rewrite` accepts at most 4,096 records. The agent framing caps the prompt at 1 MiB, schema at 128 KiB, response at 1 MiB, and probe/invocation pipes at 256 KiB. A cap or cleanup failure is reported and does not advance the applied baseline. Hidden-worker lease retry has a bounded 300 second default budget; if the process cannot start, exits, or exhausts that wait, durable work remains visible for operator catch-up. These limits and process cleanup behavior are not evidence of complete sandbox isolation: maintenance does not claim to prevent an agent from loading its local authentication or instruction configuration.

## Historical test-isolation incident

During earlier Task 9 runs, an unowned-SKILL fixture sometimes wrote `.agents/skills/fixture` while the configured output was `.agents/skills/repo`. In recorded run 440, CLI approval returned 0 and the test failed its expected exit-5 assertion. Multiple pre-fake executions are identified, including a later corrected-path run that returned 5; none had a worker/provider fake. An external adapter invocation is possible and unconfirmed, and the count is unknown. The inspected temporary attempt artifacts were absent, so retained evidence neither confirms nor rules out invocation. No credentials, provider response, network state, or executable contents were inspected.

The correction puts explicit fake probe/invoke callbacks behind the real worker seam before approval and asserts the current whole-file conflict stops before worker entry while preserving bytes. Its isolated fake-backed RED reached the fake probe before the shared preflight fix; after the fix, both SKILL and provenance collision variants passed with zero worker/probe/invoke entry. This is evidence for the corrected fake-isolated tests only; it does not resolve the earlier uncertainty. The Task 10 integration test likewise installs both fakes before the first approval and uses them for the later auto drain. No global claim that the earlier test runs made no real call is supported.
