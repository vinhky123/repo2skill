# Ledger schema compatibility

P0 ledger documents use `schemaVersion` `1.0`. Each project, run, state, manifest, manifest set, and export journal is versioned. The index is disposable and is never authoritative.

Readers reject an unknown major schema version. Within the current major version, mutable documents preserve unknown additive object fields when rewritten. Those extra fields are not interpreted by the current program and do not participate in IDs or digests. Immutable run and manifest artifacts are not rewritten. Additive compatibility does not make arbitrary edits to ledger JSON safe.

P0 does not promise automatic migration between major versions. Before moving a repository state directory to a build with a different supported schema major, preserve a copy of `.repo2skill/` and consult the release notes and this guide. If the build refuses the schema, stop using mutating commands until an explicit migration path is documented; do not change `schemaVersion` by hand. No migration command or general rollback tool is currently specified.

Commit maintenance stores its `schemaVersion: 1.0` state pointer, immutable jobs, source-context manifests, attempts, and apply journals under `<stateDir>/maintenance/`. These documents have IDs and schemas separate from P0 project/run/manifests. An absent maintenance pointer on an initialized P0 project reads as the backward-safe disabled/ask default; reading status does not create it. Maintenance state also supports additive fields within major version 1, including the optional `enabled` flag used by older documents. Reopening a P0 1.0 ledger does not require rewriting immutable runs, manifests, or export journals.

Use `repo2skill init` to create a P0 project, then `repo2skill maintain setup`, `repo2skill maintain catch-up --rebuild`, and approval of the displayed job ID to establish maintenance from a committed tree. Rebuild queues an approval-gated job and leaves the prior applied baseline and history in place until the accepted result is verified. If maintenance JSON is corrupt, `maintain status` exits 7 and reports recovery; do not delete or hand-edit the pointer or immutable job records to force a migration. `maintain disable` preserves queue/history and exported files while disabling future worker activity.
